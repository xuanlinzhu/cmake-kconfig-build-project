# 安装依赖与快速使用

## 1. 环境要求

### 1.1 Python

建议使用 Python 3.8 或更新版本。

必须安装：

```bash
pip install kconfiglib
```

`menuconfig` 由 Kconfiglib 提供，代码中会通过 `import menuconfig` 启动菜单界面。

Windows 下如果 `config` 进入菜单时报 curses 相关错误，补充安装：

```bash
pip install windows-curses
```

### 1.2 CMake

建议使用 CMake 3.20 或更新版本。

模板中使用：

```cmake
cmake_minimum_required(VERSION 3.20)
```

### 1.3 构建后端

默认模板使用 Ninja：

```text
CK_CMD_CONFIGURE = cmake -S . -B build -G Ninja
CK_CMD_BUILD = cmake --build build -j4
CK_CMD_CLEAN = cmake --build build --target clean
```

因此建议安装 Ninja。

如果不想使用 Ninja，可以在 Kconfig 中改成其他生成器。

Linux Makefile 示例：

```text
CK_CMD_CONFIGURE = cmake -S . -B build -G "Unix Makefiles"
CK_CMD_BUILD = cmake --build build -j4
CK_CMD_CLEAN = cmake --build build --target clean
```

Windows 可根据环境选择：

- Ninja
- MinGW Makefiles
- NMake Makefiles
- Visual Studio 生成器

### 1.4 编译器

标准工程需要本机 C / C++ 编译器：

| 平台 | 可选编译器 |
| --- | --- |
| Windows | MinGW GCC、MSVC、Clang |
| Linux | GCC、Clang |
| macOS | Apple Clang、GCC |

STM32 工程需要 ARM GNU Toolchain，并确保以下工具可被找到：

```text
arm-none-eabi-gcc
arm-none-eabi-g++
arm-none-eabi-objcopy
arm-none-eabi-objdump
arm-none-eabi-size
```

## 3. 快速运行标准工程

进入标准工程模板：

```bash
cd template/project/standard_project
```

打开配置菜单：

```bash
python ck_tool.py config
```

保存退出后，会生成：

```text
.config
ck_config.cmake
ck_config.h
```

生成 CMake build 目录：

```bash
python ck_tool.py build
```

编译：

```bash
python ck_tool.py make
```

自动执行完整流程：

```bash
python ck_tool.py auto
```

## 4. 快速运行 STM32 工程

进入 STM32 工程模板：

```bash
cd template/project/stm32_project
```

打开配置菜单：

```bash
python ck_tool.py config
```

生成 CMake build 目录：

```bash
python ck_tool.py build
```

编译：

```bash
python ck_tool.py make
```

STM32 工程的 configure 命令一般写在 `Kconfig` 顶部：

```text
CK_CMD_CONFIGURE = cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_TOOLCHAIN_FILE=cmake/gcc-arm-none-eabi.cmake
```

如果要切换工具链文件，优先修改这行。

## 5. 命令说明

| 命令 | 简写 | 说明 |
| --- | --- | --- |
| `config` | `c` | 打开 Kconfig 菜单，并生成 `ck_config.cmake` / `ck_config.h` |
| `build` | `b` | 删除旧 build 目录，重新运行 CMake configure |
| `make` | `m` | 执行编译命令，必要时更新版本宏 |
| `clean` | `cl` | 执行清理命令 |
| `auto` | `a` | 执行 `config -> build -> make` |
| `help` | `h` | 打印帮助 |

示例：

```bash
python ck_tool.py c
python ck_tool.py b
python ck_tool.py m
```

## 6. 命令与 CMake 的关系

CK Build 中的 `build` 和 `make` 不是传统含义里的同一个阶段。

| CK 命令 | 实际执行 | 说明 |
| --- | --- | --- |
| `build` | `CK_CMD_CONFIGURE` | 运行 `cmake -S . -B build ...`，生成构建系统 |
| `make` | `CK_CMD_BUILD` | 运行 `cmake --build build ...`，真正编译 |
| `clean` | `CK_CMD_CLEAN` | 运行清理目标 |

这样命名的原因是保持工程侧入口简洁，但阅读代码时需要注意：

```text
python ck_tool.py build   # 配置 CMake build 目录
python ck_tool.py make    # 编译目标
```

## 7. 新建工程流程

推荐复制模板，而不是从空目录开始写。

### 7.1 标准 C/C++ 工程

```bash
cp -r template/project/standard_project your_project
cd your_project
```

修改：

```text
Kconfig
CMakeLists.txt
ck_tool.py，如需自定义 Hook
```

重点检查：

```text
CK_TOOLS_ROOT
CK_WORKSPACE_ROOT
CK_CMD_CONFIGURE
CK_CMD_BUILD
CK_CMD_CLEAN
PRO_NAME
```

### 7.2 STM32CubeMX 工程

推荐先保留 CubeMX 生成的工程结构，再把 CK 模板中的关键文件合入：

```text
ck_tool.py
Kconfig
CMakeLists.txt
cmake/gcc-arm-none-eabi.cmake
```

STM32 工程需要确认：

- `Project.ioc` 是否仍由 CubeMX 维护。
- `cmake/stm32cubemx/CMakeLists.txt` 是否存在。
- 启动文件 `.s` 是否参与构建。
- 链接脚本 `.ld` 是否被 toolchain 文件或 CMakeLists 正确引用。
- `arm-none-eabi-*` 工具是否可找到。

## 8. 常见使用场景

### 8.1 修改项目名称

进入 menuconfig 修改 `project name`，或者直接修改 Kconfig 默认值：

```kconfig
config PRO_NAME
    string "project name"
    default "your_project"
```

之后执行：

```bash
python ck_tool.py config
python ck_tool.py build
python ck_tool.py make
```

### 8.2 切换 Debug / Release

标准工程可通过 `Kconfig.toolchain` 中的 Build Type 配置控制，也可以直接修改 configure 命令：

```text
-DCMAKE_BUILD_TYPE=Release
```

STM32 模板默认在 configure 命令中写了：

```text
-DCMAKE_BUILD_TYPE=Debug
```

需要 Release 时修改为：

```text
-DCMAKE_BUILD_TYPE=Release
```

### 8.3 修改并行编译数量

修改 Kconfig：

```text
CK_CMD_BUILD = cmake --build build -j8
```

### 8.4 不想每次 build 都删除 build 目录

当前 `build` 流程会删除 `CK_BUILD_DIR` 后重新 configure。

如果希望保留增量 configure，可以改 `ck_core.py` 的 `build()` 行为，或在后续版本中把该策略做成 Kconfig 开关。

当前模板选择删除目录，是为了让新手工程和交叉编译工程更稳定，减少缓存导致的工具链错误。

## 9. 建议的提交策略

| 类型 | 建议 |
| --- | --- |
| 工程模板文件 | 提交 |
| `Kconfig` | 提交 |
| `.config` | 可提交，表示默认配置 |
| `ck_config.h` | 可按项目需要提交 |
| `ck_config.cmake` | 通常不提交 |
| `build/` | 不提交 |
| `bin/` | 不提交 |
| `.config.old` | 不提交 |

如果项目把 `ck_config.h` 当作版本状态文件使用，可以提交它；如果只把它当作纯生成文件，也可以不提交。
